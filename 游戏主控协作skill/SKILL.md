# 多 agent 游戏开发 · 主控流程

主控 = 唯一维护规格与任务状态的会话。它不写游戏代码，只做：定规格、拆任务单、按证据验收、同步记录。

## 适用场景 / 不适用
- 适用：制作人 + 2 个以上执行会话（开发、资产、特效、音频、UI、修复、QA）同时推进一个游戏；需要跨会话交接。
- 不适用：单会话小改动；纯讨论。

## 输入
- 制作人的目标与审美判断（方向、画风、范围、截止日期）
- 规格中心目录（见参数）：OpenSpec change（proposal / design / specs / tasks）、`GDD.md`、`STATUS.md`、`AGENTS.md`、`DEVLOG.md`
- 引擎官方规范（例如 ForgeAX `engine-ai.md`），存档到 `contracts/`

## 步骤

### 0. 起项目
1. 规格中心用 OpenSpec 建 change；`AGENTS.md` 写角色表、写入边界、证据规则、引擎规范要点。
2. 第一张开发任务单只做「引擎基线 + 最大技术风险样板」（例如自定义后处理能否跑通）。
3. **先定画风再批量出图**：同一构图出 2–4 张「游戏内截图」目标图让制作人选，定为验收标准图；概念插画只作氛围参考。

### 1. 分工（角色 → 写入目录，互不重叠）
| 角色 | 写入范围 |
|---|---|
| 主控 | 规格中心（OpenSpec / GDD / STATUS / handoffs / DEVLOG） |
| 开发 / 集成 | 游戏目录（除特效、音频目录） |
| 资产 | `assets/`（概念图、源文件、导出） |
| 特效 / 音频 | 游戏内各自子目录，需改他人代码时写「接口请求」 |
| UI | `assets/ui/`；进游戏由开发集成或修复会话内联 |
| 修复 | 指定 bug 范围 |
| QA | 只写 `reports/qa`、`evidence/qa`，不读源码 |

### 2. 写任务单（模板：`templates/task-ticket.example.md`）
每张必须有：基线提交号 / 背景与根因线索 / 按顺序的任务 / **可量化验收**（附目标截图、像「主角占屏高 8–10%」「画面无黑色矩形」）/ 允许修改的目录 / 停止条件 / 交付物（报告路径、证据目录、提交号）。再附一段可直接复制给会话的短提示词。

### 3. 长程任务（防早收工）
- 写「待办池 + 清单做完不许停」，每项完成在 progress 追加 `[HH:MM] 完成 / 证据 / 下一项`；卡 30 分钟跳下一项；只有两种情况能结束：全部完成或到时间点。
- 只写「跑 10 小时」没用，agent 会在清单「能跑」时就停。

### 4. 并行与集成
- 并行前提：写入目录不重叠 + 共用同一 dev 服务时约定**唯一持有者**，其他人只复用、不重启。
- **集成期单一写入者**：出现「注册行被还原 / 启动失败无法归因」时，立即只留一个会话写游戏目录，其余把需求写成接口请求；交付时 git 干净，给出提交号作为三方基线。

### 5. 验收固定步骤（每次）
1. 打开证据（截图、录屏、测试输出）亲自看，对照目标图打分；agent 的自评不算。
2. 决策变化 → 当场改 proposal / design / GDD。
3. 同步 STATUS、勾 tasks、追加 DEVLOG。
4. `npm run spec:validate`。
5. 派下一单。

### 6. 质量闸门
- **真人试玩每轮必做**：自动化与 agent 自检会系统性漏掉「看起来不对、玩起来不爽」。
- **独立 QA 盲评**（`游戏QA盲评skill`）：派单者不自验。
- **在交付形态上验**：dev 能跑不等于 preview / 打包能跑，bug 要在用户实际使用的形态下复现。
- 冲突结论（A 说能、B 说不能）→ 让第三方当面复现，不选边。

### 7. 收尾
里程碑后归档 change，新里程碑开新 change；把重复流程沉淀成 skill（`SKILLS-DISTILL.md` 模式：谁做过谁写，主控审）。

## 验收标准（主控自身）
- [ ] 每张任务单含基线、量化验收、写入边界、交付物
- [ ] 每次验收后 STATUS / tasks / DEVLOG 同步，spec 校验通过
- [ ] 每个里程碑前有至少一次真人试玩 + 一次独立 QA
- [ ] 任意时刻能说清：谁在写哪个目录、当前基线提交号

## 踩坑与对策
| 坑 | 对策 |
|---|---|
| 概念图好看，游戏画面 2/10 | 先出「游戏内截图」目标图，第一张任务单就附量化验收 |
| 长程任务 1 小时就收工 | 待办池 + 不许停 + 进度时间戳 |
| 两个主策互相覆盖 | 只有一个状态维护者，其余为顾问 |
| 规格落后于决策 | 验收固定步骤第 2–3 步 |
| 三会话同写一目录 | 集成期单一写入者 + 提交号基线 |
| dev 下测不出的崩溃 | 在 preview / 打包形态下复现、二分 |
| agent 报告与实测矛盾 | 以第三方实测为准，并要求原会话更正报告 |
| 占位符提示词（【】未替换）直接发出 | 发给会话前替换；会话应按分工表自行推断并说明 |

## 公共踩坑（所有会话开工前读）
| 坑 | 对策 |
|---|---|
| `project play` 报 `browser.newPage: Target crashed` | 不是环境坏了：WorkBuddy 沙箱与引擎自带 Chromium 沙箱冲突。用 `游戏预览故障修复skill/scripts/play.sh`（系统 Chrome + `--no-sandbox` + 空 `ps`），脚本在沙箱外运行 |
| `/tmp` 下的隔离副本隔天消失 | 开工先检查，不在就按基线重建 |
| 共享 dev owner 被别人重启 / 卡 starting | 只复用不重启；需要稳定环境就用自己的隔离 preview（独立端口） |
| 安全删除护栏拦截（单轮删除 >50 文件，多为 `.forgeax` 缓存） | 停下回报；新一轮对话计数重置，或请用户确认 |
| play 锁被占用 | 排队等待，不抢锁 |
| 主工作区有他人未提交改动导致编译失败 | 在干净 worktree（基线 + 自己的改动）里验证，只提交自己的文件 |

## 交接格式
新会话启动提示词（模板 `templates/session-start.example.md`）：角色 + 主控是谁 + 先读哪些文件 + 当前已确认结论 + 任务 + 写入边界 + 回报格式。执行报告用 `templates/report.template.md`。
